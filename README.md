# IDEEEP site

Static site generator for the IDEEEP content pages.
`md-compiler` (a small Rust program under `src/`) reads Markdown from `content/` and writes a complete static site to `dist/`.
The site build itself runs no Python and needs no network.
Anything computed from code (Python output, figures) is generated ahead of time by dev-time tooling and committed, so `cargo run` only ever reads Markdown and committed assets.

## Prerequisites

- Rust toolchain (`cargo`) to build the site.
- [`just`](https://github.com/casey/just) for the task recipes.
- [`uv`](https://docs.astral.sh/uv/) for the Python tooling (output injection and figures). Each Python script declares its own dependencies inline (PEP 723), so `uv` builds an ephemeral environment per run and you install nothing by hand.
- `python3` for the prose linter and the local preview server.

## Build and preview

```bash
just build         # cargo run --release -> writes dist/
just preview       # build, then serve dist/ at http://localhost:8000
just serve         # serve an already-built dist/ (default port 8000)
just test          # run the md-compiler regression suite
just check-links   # build, then check internal links / assets / #anchors resolve
just figures-check # check committed figure SVGs are up to date with figures/*.py
```

`just` with no recipe runs `build`.

These checks (plus `just lint-prose`, `just test-scripts`, and `just python-output-check`) run in GitHub Actions on every push and pull request; see `.github/workflows/ci.yml`.

## Add a new post

A post is one Markdown file under `content/`.
Its output path mirrors its location, so `content/math/sir.md` becomes `/math/sir.html`.

1. Create the file. Pick the directory that matches the section.
   Top-level pages live directly in `content/` (for example `content/research.md`); reference pages live in a subdirectory (`content/math/`, `content/epidemiology/`, `content/programming/`, `content/diagnostics/`).
   The top-level directory becomes the page's search category.
2. Add front matter. The build reads three fields:

   ```yaml
   ---
   title: "Poisson Distribution"
   description: "Short meta description for search snippets and social cards."
   toc: true
   ---
   ```

   Only `title`, `description`, and `toc` are consumed by the generator.
   When `description` is absent the build derives one from the first paragraph.
   `author` and `date` are conventional but currently ignored by the compiler.
3. Write the body in Markdown.
   Link to other pages with relative `.md` links (`[SIR model](sir.md)` or `[Quantitative Methods](../math.md)`); the build rewrites `.md` to `.html`.
   Prose in the linted directories is one sentence per line (see below).
4. Wire it into navigation if it should appear in the navbar.
   Edit `config.yaml`: add the page slug (filename without `.md`) under the relevant `dropdowns` entry, or to `navbar_order` / `page_order`.
   Reference pages inside a subdirectory usually are not in the navbar; they are reached by links from their section's landing page, so this step is optional.

Nothing else registers a page.
`cargo run` walks `content/` and emits every `.md` file it finds (`README.md` files are skipped).

## Autogenerated output

Two kinds of output are computed from code, committed, and shown on the site.
Both are dev-time steps.
Regenerate them whenever the underlying code changes, then commit the result.

### Injected Python output

Fenced ```python blocks in the linted pages can have their stdout injected directly beneath the block, so the numbers shown on the site are real and reproducible.

```bash
just python-output        # run the blocks and inject their stdout in place
just python-output-check  # CI check: non-zero exit if any output is stale
```

How it behaves:

- Blocks on a page run top to bottom in one shared namespace, so a later block can use names defined earlier on the same page.
- Whatever a block prints is injected right after it, wrapped in `<!-- python-output:auto -->` / `<!-- /python-output:auto -->` markers.
  The step is idempotent: re-running strips the old output and regenerates it.
- Output is injected only when a block actually prints and runs without error.
  Plot-only blocks, pseudo-code, and deliberately failing examples are left untouched.
  Long output is capped.
- Only ```python is executed.
  ```r and ```julia blocks are illustrative and are never run, so keep any cross-language examples consistent by hand.

To add a computed result, write a ```python block that prints it, then run `just python-output`.
Do not hand-edit the text between the auto markers; it is overwritten on the next run.

### Figures

Illustrative figures are Python scripts in `figures/` that render committed SVGs into `assets/figures/`.

```bash
just figures       # render every figures/*.py to assets/figures/*.svg
```

To add a figure:

1. Create `figures/<name>.py`.
   Start from an existing script.
   Declare dependencies in the PEP 723 header, import the shared look from `_style.py` (`from _style import apply_style, save, PALETTE`), and end with `save(fig, "assets/figures/<name>.svg")`.
   `_style.py` is a helper, not a figure, and is skipped by the recipe.
2. Run `just figures` (or run the single script with `uv run --script figures/<name>.py`).
3. Reference the SVG from a page with a Markdown image and a real alt text, for example `![The Poisson pmf peaks near lambda.](../assets/figures/poisson-pmf.svg)`.
   Use the `../assets/...` prefix that matches the page's depth.

Use colorblind-safe colors from `_style.py`; seed any randomness for reproducibility.

## Prose convention

Prose in `content/math`, `content/programming`, `content/epidemiology`, `content/diagnostics`, `content/scientific-pathways.md`, and `content/scientific-writing.md` is written one sentence per line.

```bash
just lint-prose    # CI check: non-zero exit if a file breaks the convention
just fmt-prose     # reformat those files to one sentence per line in place
```

## Typical workflow for a new post

```bash
# 1. write content/<section>/<slug>.md with front matter and body
# 2. add any ```python blocks that print results, and figure scripts
just python-output   # inject computed output
just figures         # render any new/changed figures
just fmt-prose       # normalize prose in the linted sections
just preview         # build and eyeball at http://localhost:8000
# 3. commit the .md, the injected output, and assets/figures/*.svg together
```

CI runs `lint-prose`, `python-output-check`, and the test suite, so land those green before opening a PR.
